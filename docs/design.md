# ChordFlow 视觉与交互规范

## 方向与优先级

清晰、克制、便于长期使用的钢琴练习工作台。2026-10-18 的界面重构要求优先于早期提示词和本文件旧版：先分配钢琴与演奏操作的空间，再安排教学说明。最新一轮依据 Emil Kowalski 的 design engineering 指导，采用冷白工作面、石墨灰控件和按手别区分的音位颜色；保留已验证的信息顺序。

禁止恢复巨大的单字母和弦、重复页眉、装饰性英文眉题、导航编号、常驻鼓励语和多层圆角卡片。

## 布局

桌面导航宽 176px，顶部仅一个 56px 高的页面标题栏。主区域使用 24px 水平、18px 垂直内边距；宽屏水平内边距 32px，内容最大宽 1700px。操作区不再包在白色大圆角容器里。

桌面只由工作区承担纵向滚动，不应再出现外层文档滚动条。内容面板建立相对定位上下文，使供读屏使用的绝对定位标签、隐藏文件输入留在工作区内，避免撑高外层文档。滚到长进行底部时，使用说明之后仅保留正常内边距。

搜索与根音、类型选择器相邻排列。输入框和提交按钮共用一个边框与整组焦点提示；输入区不再单独绘制截断的粗轮廓，按钮保留键盘焦点提示。

搜索框与选择器统一为 38px 高、14px 字号、6px 圆角和相同浅边框。焦点同样采用 2px 轮廓、3px 间隔，搜索不另加透明光晕；放大镜提交按钮放在右侧，不使用内部竖分隔线。触屏字号仍遵循 16px 的要求。

和弦探索顺序固定为：

1. 根音、类型、和弦搜索。
2. 紧凑的和弦符号、中文名称、构成音、相对度数与半音公式。
3. 转位切换与最低音信息。
4. 演示键盘；音区和标记控件紧接键盘上方。
5. 唯一一组试听、停止、手别与音量操作。

1366×768 和 1920×1080 均须在不滚动时完整看到上述核心操作。默认 C 和四音和弦的高转位均纳入浏览器边界断言。通用使用说明展开、搜索错误及存储警告允许增加高度，不通过裁剪内容维持首屏。

钢琴与 224px 的弹奏指导并排；1920 宽屏指导列 250px。指导随当前和弦、实际左右手音位、转位或音型变化。根音、指法编号等通用理论放入原生 `details`，默认收起。约 1200px 以下，指导移动到键盘及播放器之后，保持可访问。

伴奏音型沿用同一键盘与播放器区域。选择音型和当前配置在上，逐步事件在键盘后。进行页面先显示进行选择与可点击和弦序列，再显示音型、键盘与事件；连接方案、加花和保存安排在后。四个和弦占满一行，较长进行在桌面使用八列，手机四列换行。我的练习使用行列表和分隔线，保留实际时间、收藏与备份入口。

## 移动端

780px 以下采用正常文档纵向滚动，移除桌面固定视口与内部纵向滚动限制。导航为四项横向按钮。选择器、紧凑和弦信息、转位、键盘、试听、弹奏指导依次排列。

播放器始终占据文档中的实际空间，不使用 fixed 或 sticky。手机允许向下滚动查看播放操作，不遮挡琴键或焦点。只有钢琴区域横向滚动，页面本身不得横向溢出；390px 和 320px 均需验证。触控主要按钮约 42–44px 高。

触屏控件输入文字至少 16px，避免 iOS 聚焦缩放；鼠标 hover 样式只在 `(hover: hover) and (pointer: fine)` 启用，触屏用按压状态确认操作。保留用户缩放能力。页面声明 viewport-fit 并为顶部和底部预留安全区。手机仍采用文档滚动，不禁止正常的下拉刷新。

## 排版、颜色与结构

- 工作面 `#F7F8FA`，交互底色 `#FFFFFF`，正文 `#20242B`；次要文字 `#626A76`。
- 主控件为石墨灰 `#303846`，右手钢蓝 `#3B5FAA`，左手琥珀 `#946133`；分隔线 `#E2E5EA`。不用整片彩色背景表示每一种选中状态。
- 正文使用本地 Geist 与 Noto Sans SC 子集，常规 14px；操作标签和次要说明通常 12–13px。部署不请求 Google Fonts 或其他外部字体 CDN。
- 和弦符号使用同一无衬线字体，桌面 40px、手机 32px；音名和节奏数据仍使用等宽字体。构成音是静态音程条，不使用像按钮一样的边框卡片。
- 品牌统一为英文 **ChordFlow**，不使用中文品牌名或 CF 拼字标记。蓝绿色图标与 Geist 英文字名横排，Flow 使用品牌色 `#157F80`；导航与 favicon 使用同一图形，琴身显示相同的英文字名。旧中文 SVG 字标及其生成步骤已移除。
- 常规控件圆角 6px，钢琴外壳 7px。使用低对比度边界与很浅的控件阴影表达可按压性；不在主操作区增加大卡片。音型选择增加勾选记号，进行当前项使用底部细线。
- 根音、左右手、加花和正在发声均含文字或符号，不仅靠颜色区分。白键普通音名提高对比度。

## 交互细节

普通按钮通过指针按下时的 `.98` 缩放确认操作，按下 100ms、释放 160ms，使用 `cubic-bezier(0.23, 1, 0.32, 1)`。只过渡 transform；颜色、边框与选中内容即时更新。

根容器记录最近一次真实 pointerdown / keydown，仅决定展示反馈。键盘触发时立即移除按压动画，不阻止事件或修改点击、音频逻辑。导航、转位、音型、事件格属于频繁操作，不使用位移动画。琴键按下与发声高亮即时显示，不补间音乐播放头。

播放、暂停、继续按钮使用固定最小宽度 102px，切换状态时不会挤动后面的控制项。节拍器和预备拍使用稳定的勾选方框辅助颜色。`prefers-reduced-motion` 下取消所有过渡和动画；focus-visible 始终可见。

字体来源、SHA-256 和许可见 `public/fonts/manifest.json` 与相邻 OFL 文件。字体子集已改名为 Chordflow Sans / Chordflow Sans SC，覆盖项目界面文字，用户自行命名中的额外字符使用系统字体回退。`scripts/build-fonts.py` 可重新生成，无需在普通 npm 构建中执行。

## 试听与练习播放器

和弦探索只保留键盘下一组“同时弹 / 逐音上行 / 逐音下行 / 停止”。原底部第二组试听入口移除。附近显示试听对象、实际发声状态、结束或停止状态。琴键单音也显示具体音名。状态由已有音频活动与 UI 状态呈现，不新增音频时钟。

伴奏与进行使用连续练习播放器，显示进行或和弦名称、音型、正在播放 / 暂停 / 停止 / 本轮完成；保留速度、手别、循环、节拍器和预备拍。停止按钮始终独立可见。采样音源、加载进度、降级原因和重试入口位于同一区域，主音量不改变原有持久化行为。

播放、节拍、按音、音区算法和数据模型继续来自原有 music / audio / storage 模块。此次不引入路由同步、重新编排节奏或修改备份格式。

## 音区与乐理

自动适配仍覆盖全部演示事件，进行播放中保持稳定。手动 C2–C5、C3–C6、C4–C7 选项保留；手动范围外的演示音给出恢复入口。音区菜单仅调整键盘显示，音型的演奏音区另行控制。

手机白键最小约 24px，琴键局部滚动。自动模式初始把演示按音居中，播放头不抢回用户拖动的位置。C4 = MIDI 60；理论拼写和实际 MIDI 音高保持分离。

扩展音型与完整跟练样例继续使用展开入口。加花事件显示文字及虚线，经过音不混入完整和弦构成说明。

## 可访问性与检查

保留原生按钮、表单 label、ARIA 当前页及选中状态、跳转主内容入口、清楚的 `focus-visible`。琴键可 Tab 聚焦后 Enter / Space 发声。状态更新使用 live 区域，搜索错误紧邻表单，所有图标按钮有名称。交互遵循 `prefers-reduced-motion`。

采用 frontend-design、Emil 的 emil-design-eng / mobile-native / review-animations 审视本次修改；已有 Vercel web-design-guidelines 的可访问性要求继续适用。URL 状态同步、路由链接和既有数据操作行为等建议属于后续功能设计，本次遵守“保留功能逻辑”的约束，不扩展路由或改变删除流程。
